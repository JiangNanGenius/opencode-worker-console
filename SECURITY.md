# Security

Worker Desk is a single-administrator application. The console requires a password and can optionally listen on a LAN interface or sit behind an HTTPS reverse proxy with explicitly allowed origins. OpenCode itself must remain on loopback. A signed-in administrator can use the worker runtime with the host user’s execution privileges; login is not multi-tenant isolation. Fresh installs use the documented `admin` / `admin` default; set a private password before enabling network access. Passwords are stored as salted PBKDF2 hashes, sessions expire and can be revoked, and changing the password invalidates existing sessions. See [remote access](references/remote-access.md).

Credentials stay in the existing OpenCode credential store and the owner-only runtime directory. The console uses a local session cookie and supplies OpenCode server authentication in the backend; the bridge does not place provider credentials or the server password in browser data. It does not redact the raw native OpenCode gateway, its process logs or arbitrary tool output, which are not guaranteed to be credential-free and may already appear in native session history. Deliberate authentication transport (loopback Basic auth, an injected process-environment password) is separate from keeping values out of prompts and tasks. Do not include keys, private prompts or logs in issues or screenshots.

Provider authentication is owned by OpenCode; the bridge server password is generated locally and owner-only; deployment or application credentials should use an existing authenticated login or tool. When no such tool exists, `credential register` stores metadata only (an owner-only private file path, or an environment variable name) and `credential run` resolves the reference in-process, injects it only through the child environment and redacts captured output plus common encodings. There is no value-retrieval command and no plaintext argument. On timeout or output-cap termination the child process group is killed and the captured buffers are suppressed. This is exposure reduction for normal authorized workflows, **not a sandbox**: a child or the same-user agent can deliberately bypass it, non-captured side effects and external logs are not covered, and not every arbitrary text secret is detectable. Late bridge redaction cannot erase values already present in native OpenCode history, saved artifacts or prompts. Removing a reference or rotating a value does not rewrite historic data. Never place secret values in chat, prompts, steer text, command substitution or command flags. See [references/credentials.md](references/credentials.md).

Workers run with the calling user's filesystem privileges. Auto Approve is enabled by default in this dedicated service: all tool permissions allow execution without prompts. Task scopes and read-only intent are cooperative instructions, checked through resulting changes, not a sandbox. You can disable Auto Approve for native tool scopes and exact shell allowlists; shell commands can still do anything their dependencies can do. OpenCode's native UI also provides actions outside the worker queue.

Tasks, code snapshots and reports remain private local data. Do not commit the runtime state directory. Permanent session deletion requires explicit title confirmation and checks for active descendants. It removes OpenCode history, while the worker ledger and evidence remain.

For a suspected vulnerability, use the repository's private vulnerability reporting channel if available. Otherwise open an issue requesting a private contact without disclosing exploit details or personal data.
